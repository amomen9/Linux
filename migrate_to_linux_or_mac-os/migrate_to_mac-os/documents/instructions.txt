 CURRENT ARCHITECTURE (authoritative - read this first)
===============================================================================
The project was refactored to a UNIVERSAL, single-set installer. The detailed
sections further below predate that refactor and remain useful for the detection
logic and the per-app research, but where they conflict with this block, THIS
BLOCK WINS.

Pipeline (one entry point):
  run_project.ps1  (project root) orchestrates:
    1-3. Detection (submodules/C_, B_, A_*.ps1) -> writes CSVs to  documents/
    4.   Generator (submodules/D_compile_and_generate_shell_script.ps1) -> writes
         ONE universal installer set to  "Execute on macOS!/"

Layout:
  Migrate to macOS/
    run_project.ps1
    Additional_Manual_macOS_Software_Requirments.csv   (hand-curated hardcoded apps)
    Supported Versions and Architechtures.txt          (macOS releases newest-first + "best for" note, CPU arches, minOS, per-channel coverage)
    README.md / README_fa.md
    submodules/      A_/B_/C_ detection, D_ generator, docker_discovery.sh/.ps1,
                     templates/ (_common.sh engine + 4 *.sh.tmpl)
    documents/       A_/B_/C_ CSVs, B_applications.json manifest, this file
    Execute on macOS!/   GENERATED universal scripts (execute_all / install_* / apply_settings)

Universal installer model:
  - The generated *.sh detect the macOS RELEASE at runtime via `sw_vers`
    (Tahoe 26 / Sequoia 15 / Sonoma 14 / Ventura 13 / Monterey 12 / Big Sur 11 /
    Catalina 10.15; an unknown newer release is reported as "macOS <major>" and still
    runs) and the CPU ARCH via `uname -m` plus `sysctl -n sysctl.proc_translated`, so a
    Rosetta shell on an Apple Silicon Mac is still recognised as arm64. One set runs on
    EVERY supported macOS version and on BOTH architectures - there are NO per-version
    folders. Rosetta 2 is installed on demand for Intel-only software (and for Wine).
  - CASK-FIRST: GUI apps install from Homebrew Cask (the token is identical on every
    macOS version and on both architectures - Homebrew picks the matching build).
    Homebrew formulae cover CLI/dev tools, `mas` covers Mac App Store-only apps, and
    MacPorts is honoured when it is the package manager the machine actually has.
  - Apps whose macOS counterpart SHIPS WITH THE OS (Finder, Preview, Calculator, Disk
    Utility, Time Machine, Screenshot, Activity Monitor, ...) use method "builtin":
    nothing is installed, but the app is still reported with how to open it, so the
    migration report never loses track of a Windows app.
  - The engine (submodules/templates/_common.sh) provides: detect_os, detect_arch,
    os_at_least, ensure_rosetta, ensure_brew/ensure_cask/ensure_mas,
    pm_install/pm_installed/pm_refresh, install_cask/install_mas, and the
    multi-strategy install_app (cask/brew/native/mas/builtin/webapp/docker/
    wine-crossover/dmg-url/pkg-url/script/manual). The generator inlines it into each
    output script (standalone, LF newlines, no BOM).
  - Homebrew REFUSES to run as root and the stages run under sudo, so every `brew` call
    is dropped back to the logged-in user (`brew_run`). Because some casks ship a .pkg
    payload and call sudo themselves, the engine writes a RUN-SCOPED
    /etc/sudoers.d/migrate_to_macos_tmp granting that user NOPASSWD for exactly the
    binaries Homebrew Cask uses, validates it with `visudo -cf`, and removes it again in
    an EXIT/INT/TERM trap. Set MIGRATE_NO_SUDOERS=1 to opt out (installs then prompt).
  - Everything is written for the bash 3.2 and the BSD userland macOS ships: no GNU
    coreutils, `stat -f`, `sed -i ''`, `mktemp -t`, `dscl` instead of getent, `ditto`
    instead of `cp -a`, and `lsof` instead of `ss`.

Manifest schema (documents/B_applications.json):
  Each installed alternative carries an "install" object the generator reads:
    install: { method, caskId, masId, builtinApp, native:{brew[,port]},
               arch:[arm64,x86_64], minOS:"13", downloadUrl:{x86_64,arm64,dmg,pkg},
               webappUrl, dockerImage, githubRepo, scriptUrl, repo:{brew[,port]},
               downloadPage, postInstall:[...], note, review }
    native.port (MacPorts) is OPTIONAL; when omitted the engine falls back to the brew
    formula name (the two projects track upstream names closely, and a miss just falls
    through to the next backend and finally to the download page).
    minOS is the minimum macOS major version ("13", "10.15", ...). On an older Mac the
    app is SKIPPED with an explicit reason instead of failing halfway through.
  method in: cask | brew | native | mas | builtin | webapp | docker | wine-crossover |
             dmg-url | pkg-url | script | manual.  "review:true" flags a token that
             still needs verification on a real Mac (cask tokens do get renamed upstream).
  - install.scriptUrl (method "script"): the vendor's official install script. install_app
    DOWNLOADS it first (so an HTML/error page is never piped to a shell) then runs it as
    root. Used for vendors that only publish a curl-pipe installer (e.g. Ollama).
  - install.repo: a shell snippet (keyed brew/port) to add a VENDOR TAP before the
    install. The generator turns it into a repo_setup_<slug>() function that install_app
    runs before the cask/formula install. It is rarely needed on macOS: Homebrew's
    default taps already carry Google, Microsoft, Docker, Node, PostgreSQL, VS Code and
    the rest, which is why the Linux edition's eight vendor-repo blocks are all gone.
  - install.postInstall: an ARRAY of self-contained shell snippets run RIGHT AFTER the
    app installs successfully (the app's "custom post-install commands"). The generator
    emits one --post 'CMD' per entry; install_app runs them as the logged-in desktop user
    (via run_as_user, which uses `launchctl asuser` so `defaults`/`open`/`osascript`
    reach the real GUI session) ONLY when the app was freshly installed this run. A
    failing command is reported but never fails the install.
  - "forceInclude": true (top-level on an app entry) emits that app EVEN WHEN it is not
    detected on Windows -- for macOS-only helpers the user always wants (e.g. CopyQ, the
    clipboard manager that replaces the Windows Win+V history but has no Windows app to
    detect). De-duped by name against detected apps and the Additional CSV.

Docker capture/rebuild flow:
  submodules/docker_discovery.sh (or .ps1, identical PowerShell port) snapshots local
  Docker (images/volumes/networks/containers) and EMITS a cross-platform bash
  docker_rebuild.sh into BOTH submodules/ and "Execute on macOS!/" (auto-starts Docker
  if stopped; volume DATA is not preserved).
  - B_detect_installed_windows_software.ps1 automatically runs docker_discovery.ps1
    when Docker is installed on the Windows source (so docker_rebuild.sh only exists
    when the source had Docker).
  - SERVER SOFTWARE WITH A NATIVE LINUX BUILD (e.g. Microsoft SQL Server) follows its
    Windows topology automatically: installed on the HOST OS on Windows -> detected as a
    program -> native host install on macOS via the manifest (mssql-server through
    Docker on macOS - the mssql image is amd64-only, so Apple Silicon needs Rosetta
    emulation in Docker Desktop or the native-arm64 azure-sql-edge image).
    Run as a CONTAINER on Windows -> captured by docker_discovery -> recreated as a
    container by docker_rebuild.sh. The two paths are mutually exclusive by how it is
    detected, so it is never installed twice.
  - The generated execute_all.sh asks the STAGE questions up front (each shown with
    its (y/n) option): drivers / apps / settings, plus "Migrate docker components?"
    (only if a sibling docker_rebuild.sh exists). It runs the chosen stages
    unattended, then the docker rebuild if requested. The apps stage also asks how
    many best alternatives to install ("...(excluding wine - Windows emulator)") and,
    as the LAST question, "Install the non-cross-platform Windows applications under
    the Windows emulator (wine) too? (y/n)" (sets MIGRATE_WINE_NONCROSS). All answers
    persist to migrate.config.
  - DRY-RUN / REPORT-ONLY: execute_all.sh --dry-run (also --report-only, -n, or
    MIGRATE_DRY_RUN=yes) prints the full per-app plan and makes NO changes (no root
    required); only the apps plan is simulated - the driver/settings/docker stages are
    skipped.
  - MANUAL DOWNLOADS run LAST. Apps flagged install.promptFile=true in the manifest
    are excluded from install_must_have_software.sh and collected into the
    MANUAL_APPS array in execute_all.sh. For each, execute_all shows what to download
    and asks for the installer PATH - typed in single quotes, a full path or one
    relative to the user's ~/Downloads - with choices ('installer path'/skip/skip all);
    the file is installed by extension (red error + re-ask on a bad path), looping
    until a valid path is given or the user skips. The prompt shows the macOS
    alternative's name. The SAME 'installer path'/skip/skip all scheme is used by every
    download-by-user fallback in the engine.
  - VERIFICATION + UNINSTALL: after each install the engine re-checks the
    cask/formula/Mac App Store app is present (else it is marked UNVERIFIED, not OK);
    an app already sitting in /Applications is detected too and skipped; every
    successful install is ledgered and an uninstall_migrated_apps.sh is written to the
    user's home folder.

Settings migration (much broader than the original 6 categories):
  - C_detect_windows_settings.ps1 now extracts ~26 categories into
    documents/C_windows_configs.csv. Each row carries SEVEN columns:
    Category, ConfigKey, WindowsValue, macOSCommand, Notes, Phase, Scope.
      * Phase = pre | post  -> pre rows are applied BEFORE apps install; post rows
        AFTER (they need the apps/desktop to exist: shortcuts/pins -> .desktop
        favourites, startup items, services, scheduled tasks, default browser,
        ~/.ssh, Contacts, wallpaper).
      * Scope = User | System -> whose setting it is. System rows are machine-wide
        (systemsetup/pmset/networksetup/pfctl/socketfilterfw/lpadmin//etc/hosts).
        User rows are per-user `defaults` domains
        are written as SYSTEM-WIDE dconf defaults (/etc/dconf/db/local.d) so they
        written AS the logged-in user through `launchctl asuser`, never into root's own
        preference domain.
    Categories: Power, Display, Keyboard, Telemetry, AutoUpdate, Screen, Mouse,
    Touchpad, Accessibility, Time (timezone + non-Microsoft NTP), Locale, Proxy,
    Appearance (dark/light, accent, night-light), DefaultApps (default browser),
    Hosts, Printers, NetConfig (static IP/DNS - manual note only), Wifi, Firewall,
    Shortcuts, Startup, Services, ScheduledTasks, SSH, Contacts, Wallpaper.
  - apply_settings.sh runs in PHASES: `apply_settings.sh pre`, `apply_settings.sh
    post`, or no arg = both. execute_all.sh runs pre BEFORE the app install and post
    AFTER it.
  - FIREWALL -> pf port rules in ONE anchor (/etc/pf.anchors/migrate_to_macos,
    referenced from /etc/pf.conf, validated with `pfctl -n` before loading);
    program-scoped Windows rules (bound to a
    specific .exe, or "any port") cannot be expressed as port rules, so they are
    recreated with the macOS Application Firewall (`socketfilterfw --add/--blockapp`),
    which is program-scoped BY DESIGN - so on macOS this is the native shape of the rule
    and needs no third-party tool at all. Windows service-keyword ports
    (PlayToDiscovery/mDNS/...) are translated to real ports or skipped with a note.

TRANSFER PASSWORD + ENCRYPTED PERSONAL-DATA BUNDLE:
  - One SHARED transfer password (OpenSSL AES-256-CBC / PBKDF2, "Salted__" format)
    protects every exported secret: WiFi pre-shared keys (encrypted inline in the
    CSV) AND the personal-data archive.
  - Personal files (~/.ssh in full incl. private keys, the Contacts folder, the
    desktop wallpaper) are staged into "Execute on macOS!/migrated_user_data/", then
    tar'd and encrypted into ONE file "Execute on macOS!/migrated_user_data.tar.enc";
    the clear-text staging dir is then DELETED, so no unencrypted personal data is
    ever left on disk. No password / no openssl / no tar => personal data is simply
    not migrated (never left in the clear).
  - WINDOWS side: run_project.ps1 shows a mega-title and prompts for the password
    ONCE up front (15s timeout), then hands it to C_detect via $env:MIGRATE_XFER_PWD
    (shared helper submodules/_xfer_password.ps1: Show-MegaTitle / Get-XferPassword).
    Non-interactive: -EncPwd / -enc_pwd / --enc_pwd[=]SECRET. openssl is resolved
    from PATH / Git-for-Windows / winget-installed on demand.
  - LINUX side: execute_all.sh asks for the password ONCE up front
    (ask_xfer_password, cached in MIGRATE_XFER_PWD) and VERIFIES it actually decrypts
    the archive (xfer_pwd_check) so a typo is caught early; if openssl is missing it
    offers to install it (sensitive data cannot be restored otherwise). Non-
    interactive: --dec_pwd[=]SECRET. The post settings phase unpacks the archive
    (unpack_stage) and restores ~/.ssh (perms 600/700), Contacts and wallpaper; WiFi
    keys are decrypted as each network is added with
    `networksetup -addpreferredwirelessnetworkatindex` and stored in the System keychain.

STEP 6 - USER & APPLICATION DATA BACKUP / RESTORE (data-driven):
  - Config: documents/D_data_migration.json (copied to Execute on macOS!/submodules/
    at generation time). userProfile.inclusions = static important profile parts
    (Desktop/Documents/Pictures/Music/Videos/Downloads/.gitconfig/.config -> ~/).
    applications.<key> declares up to two scopes: 'userdir'
    (userdir_safe_to_transfer_to_corresponding_paths_for_macos) and 'system'
    (safe_to_transfer_to_corresponding_paths_for_macos); each with sources[],
    macTarget, DataTransferInclusions/Exclusions regex (exclusions override), and
    optional contentRewrites. Safe values: yes | yes-after-rewrite | 'same version' | no.
  - WINDOWS side: submodules/E_backup_user&application_data.ps1 (offered by run_project
    step 6: y/n, 15s, default YES). Collects verbatim, EXCLUDES cloud-restorable data at
    collection time - any path under a cloud-sync root (OneDrive/Dropbox/Google Drive/
    iCloud/Box; detected via env vars, OneDrive registry accounts, Dropbox info.json,
    Google DriveFS, and HKLM SyncRootManager\*\UserSyncRoots), any file with the
    online-only/recall attributes (0x1000/0x40000/0x400000), and ALL browser profile
    data - whether or not downloaded locally. ~/.ssh + Contacts are excluded here (they
    ship in migrated_user_data.tar.enc) but listed. Archive -> Desktop, SAME transfer
    password (unencrypted if none). Format chosen by --archive-format[=]VALUE:
      * zip    (DEFAULT) single-stage compress + AES-256 encrypt via 7-Zip -> .zip
      * 7z     single-stage compress + AES-256 encrypt (encrypted headers) via 7-Zip -> .7z
      * enctar tar + gzip(-6) + OpenSSL AES-256-CBC/PBKDF2 -> .tar.gz(.enc); OpenSSL preferred
               64-bit and streamed via stdin so a 32-bit OpenSSL also works on multi-GB files.
    Tool acquisition is robust + fail-fast: Initialize-BackupTools runs at the VERY START (before
    any staging) and, for the tool the chosen format+encryption needs, tries: already-installed ->
    winget -> Chocolatey -> (7-Zip only) standalone 7za bootstrap (7zr.exe from a stable URL
    extracts 7za.exe from the GitHub "extra" package; no admin/pm). Automatic install needs
    internet, so it is checked first (Test-Internet); if the REQUIRED tool is absent AND
    uninstallable (no internet or no method), it prints the exact reason and EXITS immediately.
    An unencrypted zip needs NO external tool (plain .NET System.IO.Compression zip fallback).
    OpenSSL is auto-installed for enctar+password (winget/choco, or Git which bundles it). Exit codes AND
    output size are validated (fails loudly instead of writing a garbage archive; disk-full is
    stated explicitly). Report table (<=30 rows else log-only), size + free-space precheck
    (peak ~2x source; confirm if tight or >50GB), progress bars. Staging is freed BEFORE the
    (enctar) encrypt so staging+archive+enc don't pile up. Auto-cleans temp leftovers
    (mtl_backup_* / mtl_*.tar.gz / mtl_*.cmd) from this and any previous/aborted run; only the
    final archive + .log remain on the Desktop, and "The staged/temporary files have been
    deleted." is printed on every path (success or failure).
    Flags: --data-backup runs the FULL pipeline but auto-confirms the two step-6 prompts
    (the "Back up now?" y/n AND E_'s low-space confirmation), yes with no timeout wait,
    leaving other prompts (password) normal. --data-backup-only skips detection+generation
    and creates just the archive with NO prompts at all. Both forward -AssumeYes to E_.
    Optional --enc_pwd SECRET encrypts non-interactively.
  - LINUX side: submodules/restore_user_and_application_data.sh, called by execute_all.sh
    after apply_settings post (self-gating: prompts 'archive file path'/s=skip, then
    'restore path'/s=skip for the deviated dir). Reads the manifest via jq, detects the
    archive format by magic ("PK"->zip, "7z"->7z, "Salted__"->enctar-encrypted, else plain
    tar.gz): zip/7z are extracted with 7z (p7zip/7zip auto-installed via ensure_7z per family -
    Homebrew `sevenzip` -> 7zz, or `p7zip` -> 7z), enctar via
    openssl|tar. Decision table = safe value x runtime
    (4/10) MIGRATE_VERSION_MODE: yes->promote to macTarget; yes-after-rewrite->rewrite
    text configs (winpath_to_macos / userprofile_to_home / drive_map / find-replace,
    always keeping .bak) then promote; 'same version'->promote iff mode==same else
    quarantine; no->quarantine. Static profile data always -> ~/. chown to TARGET_USER.
    Ends with the deviated-dir location + a manual-promote-at-your-own-risk + test-after
    warning. Wine apps (wine:true) target ~/.wine/drive_c (__TARGET_USER__ token) and are
    never rewritten.
  - Slug bridging archived apps/<slug>/ dirs to manifest keys MUST match on both sides:
    lowercase, space->'-', strip non [a-z0-9_-] (ps1 Get-Slug == bash slugify == the jq
    ascii_downcase|gsub(" ";"-")|gsub("[^a-z0-9_-]";"")).

To regenerate the installer after editing the manifest or CSVs:
  .\run_project.ps1 -SkipDetection      (regenerate scripts only)
  .\run_project.ps1                      (full: detection + generation)

PURPOSE
-------
This file is a self-contained specification. An AI engine (or a human) should be
able to read ONLY this file - and regenerate, with the latest up-to-date data:

  0. run_project.ps1                              (Windows one-shot orchestrator:
                                                config → software → drivers)
  1. B_detect_installed_windows_software.ps1   (Windows inventory + macOS rating)
  2. B_installed_windows_software.csv          (the report the script produces)
  2b. Additional_Manual_macOS_Software_Requirments.csv  (hand-curated: hardcoded apps that
                                                  the installer includes regardless
                                                  of whether they appear in the
                                                  Windows-generated CSV)
  3. <Target OS>/install_must_have_software.sh   (one unattended installer per
                                                  target-OS subdirectory)
  4. C_detect_windows_settings.ps1            (Windows settings scraper:
                                                  power/lid, display, keyboard,
                                                  telemetry/location, auto-update)
  5. <Target OS>/apply_settings.sh           (SELF-CONTAINED settings runner: the
                                                  apply functions + dispatch table
                                                  + CSV runner in ONE file)
  6. A_detect_installed_drivers.ps1            (Windows device-driver inventory +
                                                  macOS driver/module mapping)
  7. A_installed_windows_drivers.csv           (the driver report the script produces)
  8. <Target OS>/install_device_drivers.sh   (driver installer: live hardware
                                                  detection + manufacturer firmware)
  9. <Target OS>/execute_all.sh              (one-shot orchestrator: runs settings,
                                                  apps, drivers - continue-on-error)

Everything below reflects exactly what these artifacts must do. When data such as
"the best macOS alternative", version numbers, repository URLs or package names is
required, RESEARCH IT FRESH FROM THE WEB at generation time (the values baked into
the current files were researched in June 2026 and will drift).

WORKFLOW (IMPORTANT - the human runs the PowerShell steps)
----------------------------------------------------------
Step W0  For a full one-shot inventory, the HUMAN can run run_project.ps1 on Windows:
             powershell -ExecutionPolicy Bypass -File run_project.ps1
         This runs config → software → drivers in sequence, producing all three
         CSV files at once. See the script's -Help for parameters.

Step 1  The AI generates / updates B_detect_installed_windows_software.ps1.
Step 2  The HUMAN runs that .ps1 on the Windows machine being migrated:
            powershell -ExecutionPolicy Bypass -File B_detect_installed_windows_software.ps1
        (optionally with -Online). This produces B_installed_windows_software.csv.
        The AI must NOT fabricate the machine-derived rows; they come from this run.
Step 3  The HUMAN tells the AI to proceed with the CSV.
Step 4  The AI reads B_installed_windows_software.csv and generates / updates the
        per-target-OS installer (<Target OS>/install_must_have_software.sh) from the
        rows whose "Must be included on macOS" = yes, following the INSTALLER SPEC.
Step 5  The HUMAN runs the installer as root on the target OS.


===============================================================================
 PART A - POWERSHELL INVENTORY SCRIPT SPEC
 (file: B_detect_installed_windows_software.ps1)
===============================================================================

GOAL
  Produce a clean, de-duplicated inventory of all REAL installed Windows software
  and rate each app for migration to macOS. Output B_installed_windows_software.csv
  beside the script (UTF-8, -NoTypeInformation).

PARAMETERS
  -OutputPath <path>            default: B_installed_windows_software.csv beside script
  -MustIncludeThreshold <int>   default: 70   (see "Must be included" below)
  -IncludeSystemComponents      switch, default off
  -IncludeStoreApps <bool>      default: $true
  -Online                       switch, default off (live Repology lookups)

ERROR HANDLING (critical - must not crash on missing properties)
  Some registry keys returned by Get-ItemProperty and some Appx packages returned by
  Get-AppxPackage can lack properties that the script expects (e.g. a registry key
  with no values has only PS* provider properties, no DisplayName). Accessing a
  non-existent property can throw PropertyNotFoundException under certain PowerShell
  configurations. Therefore:
    * Wrap Get-ItemProperty and Get-AppxPackage calls in try/catch that returns @()
      on failure.
    * Every property access inside Where-Object and Select-Object blocks MUST be
      guarded with try/catch:
        try { $_.DisplayName } catch { $null = $dn }
        try { $_.IsFramework } catch { $false }
        try { $_.SignatureKind } catch { '' }
        ...and so on for every property accessed on objects from these cmdlets.
    * This applies to: DisplayName, SystemComponent, ParentKeyName, ParentDisplayName,
      WindowsInstaller, UninstallString, DisplayVersion, Publisher (Win32);
      IsFramework, SignatureKind, NonRemovable, Name, Version, Publisher (Appx).

COLLECTION (machine-derived; read live, never hand-authored)
  Win32 apps: enumerate these registry uninstall hives -
      HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*
      HKLM:\Software\Wow6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*
      HKCU:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*   (do not omit HKCU)
    Keep rows with a non-empty DisplayName, and drop rows where SystemComponent=1,
    or ParentKeyName/ParentDisplayName is set, or it is an orphaned MSI row.
    Capture: Name=DisplayName, Version=DisplayVersion, Publisher, Source='Win32'.
  Store/UWP apps (when -IncludeStoreApps): Get-AppxPackage, dropping IsFramework,
    SignatureKind='System', NonRemovable, and a noise regex covering runtimes,
    media/image/speech extensions, vendor control panels, and OS plumbing.
    Make names human-friendly (e.g. Microsoft.WindowsCalculator -> "Windows
    Calculator") via a small override map plus a CamelCase splitter.

NOISE REMOVAL (the user's "no redundant entries" rule)
  Exclude Windows updates/hotfixes: KB numbers (also cross-check Get-HotFix),
    "Security Update", "Hotfix", "Service Pack", "Cumulative Update", "Update for".
  Unless -IncludeSystemComponents, also exclude redistributables, runtimes,
    drivers, and SDK/installer fragments (Visual C++ Redistributable, .NET runtimes,
    *Driver*, chipset/serial, ODBC/OLE DB drivers, WinFsp, OpenAL, VS Installer,
    Help Viewer, maintenance services, etc.). Keep these patterns in clearly-named,
    editable variables.

NAME CLEANING + DE-DUPLICATION
  Clean display names: strip "(remove only)", "(User)", trailing architecture
    parentheticals "(x64)/(64-bit)/(64 bit)" and trailing bare arch words.
  De-dup KEY keeps version digits (so genuinely distinct versions - e.g. three
    Python installs - remain separate) but drops vendor prefix, parentheticals and
    punctuation, so cosmetic Win32-vs-Store duplicates collapse. Prefer the Win32
    record when a collision occurs.

THE 12 CSV COLUMNS (exact header text, in this order)
  Name                        (machine)
  Version                     (machine)
  Publisher                   (machine)
  Source                      (machine: Win32 | Store)
  macOS Availability          (curated; flags - see below)
  Best macOS Alternative      (curated; see paid->free rule below)
  Alternative Competency      (curated; e.g. "100%", may exceed 100%)
  Pricing model               (curated; Free (FOSS) | Free | Freemium | Shareware | Paid)
  Must be included on macOS   (DERIVED in code; yes | no)
  Can be synched to macOS alternative
                              (curated; whether the app's data can be AUTOMATICALLY
                               synced into the macOS alternative by signing in (cloud):
                               "Yes" | "No, manual transfer". Blank only for Needs-Review
                               rows. Sourced from the manifest's Syncability field.)
  macOS Alternative Type      (curated; how the alternative is delivered - e.g. WebApp,
                               Native (Homebrew Cask / Homebrew formula / Mac App

 PART C - PER-TARGET-OS INSTALLER SPEC
 (file: <Target OS>/install_must_have_software.sh)
===============================================================================

SCOPE
  One installer per target-OS subdirectory. It installs the macOS counterpart of
  EVERY CSV row flagged "Must be included on macOS" = yes. The example target is
  the current macOS release (Homebrew Cask base). For a different target OS,
  translate the same intent to that OS's package managers and repositories.

EXECUTION MODEL
  * Bash 3.2 (what macOS ships), assumed to run as ROOT (verify EUID 0; exit otherwise).
  * Fully unattended. Homebrew must NOT run as root, so every brew call is dropped back
    to the logged-in user; the run-scoped sudoers.d rule keeps .pkg-payload casks from
    stopping to ask for a password.
  * Idempotent: if an app is already installed, run its UPDATE path instead of
    reinstalling.
  * Never abort the whole run on one failure - wrap each install, record
    OK/FAIL/SKIP, and print a summary at the end.
  * CLEAN TERMINAL UI: save the real terminal on a spare fd (exec 3>&1 4>&2) and
    redirect everything else to a log file (exec >>"$LOG" 2>&1). Print ONLY the
    curated lines to fd 3 - "==> <step>" headers and indented "installed:/updated:"
    detail - so package-manager noise never reaches the screen. Prompts and the final
    summary also go to fd 3; show the log path at start and end.
  * LIVE PROGRESS (not just a spinner): while a step runs, show a SINGLE transient
    line on fd 3 that updates in place with real progress, and CLEAR it the moment that
    step's process terminates (leaving only its "installed:" result). The progress line
    format differs by operation type:

    **Downloads** (curl/wget): use curl's hash-bar (`curl -#`) which prints a
    self-overwriting progress meter to stderr - tail it and display to fd 3. See the
    `download_file` function.

    **Installations with native progress** (brew, pip, docker pull):
      - brew: Homebrew prints its own per-package progress; keep it and suppress the
        rest (HOMEBREW_NO_ENV_HINTS=1, HOMEBREW_NO_AUTO_UPDATE=1).
      - docker: `docker pull` already prints layers + status - tail from output.

    **Installations without progress API** (Wine .exe, .pkg scripts, tar extraction,
    conda, snap, dpkg -i): these commands can produce many lines of verbose output.
    Instead of showing their last output line (which may be a random diagnostic),
    show a **non-interactive auto-progress indicator** - a live elapsed-time counter
    ("running… 45s") - while the command runs, and redirect ALL its output to the
    log. See the `run_spin_quiet` function. This keeps the UI clean and avoids
    printing confusing internal output while still confirming the step is active.

    This is essential for very long installs (e.g. texlive-full) so the user can see
    it is progressing without being overwhelmed by raw package-manager output.
  * FAILURE HELPER (_fail_with_file): when a downloaded .dmg / .pkg / .exe / script fails
    to auto-install (even the dpkg -i fallback), print the downloaded file's full
    path and the exact manual command to retry (e.g. "sudo dpkg -i <file> && sudo
    installer -pkg <file> -target /"). This avoids silent failures and gives the user a
    clear next step. The download directory (/opt/migrate-downloads) is created
    with mode 0777 and chown'd to the invoking non-root user ($SUDO_USER) so all
    downloaded files are fully accessible without sudo for inspection or manual
    install.

  * TWO LOG FILES (both printed at the end):
      - install.log         : the full, verbose command output (for deep debugging).
      - install-results.log : a SHORT results log - one tab-separated line per step,
        "<timestamp> <status> <item> <reason>", where status is OK / FAIL / SKIP and
        <reason> is a concise failure reason. Capture the reason by teeing each step's
        output to a temp file inside the spinner helper and, on non-zero exit, pulling
        the last error-looking line (grep -iE 'error|unable|^E:|curl:|dpkg:' | tail).
        For a grouped package step, list the failed package(s) + their reason. End the
        results file with a totals line (OK / manual / skipped / failed counts).

AUTO-DETECT THE TARGET ENVIRONMENT (nothing hard-coded)
  Detect at runtime, on the machine the script is executing on, and use these
  everywhere a repo line, download URL or package name needs them - never hard-code
  amd64/x86_64 or a distro release:
    * macOS release + build: `sw_vers -productVersion` / `-buildVersion`. Derive
      OS_MAJOR / OS_MINOR and a comparable OS_RELEASE (11+ uses the major; the 10.x era
      uses 10.<minor>), plus the marketing codename. Use os_at_least for every
      version-gated decision, and NEVER hard-code a release.
    * Architecture: ARCH = `uname -m` mapped to arm64 | x86_64. A Rosetta-translated
      shell reports x86_64, so also read `sysctl -n sysctl.proc_translated` and treat 1
      as arm64 - otherwise an Apple Silicon Mac would be handed Intel builds.
    * Homebrew prefix: /opt/homebrew on arm64, /usr/local on Intel. Resolve `brew`
      by probing both, never by assuming PATH.
  If an app has no build for the detected architecture (some Intel-only vendor apps),
  install Rosetta 2 and continue; if it genuinely cannot run (e.g. VirtualBox on Apple
  Silicon), constrain it with install.arch so it is SKIPPED with a reason, not failed.
  If it needs a newer macOS than this Mac, constrain it with install.minOS instead.

  vendor repos or main archives lag. Detect the codename and conditionally add:
    * dotnet/backports PPA - the Microsoft prod repo only carries .NET 8.0 on noble;

TRUSTED SOURCES ONLY (hard rule)
  Every package, repository, key, .deb, script, and binary fetched by the installer
  MUST come from an absolutely trusted, verifiable source. Apply these checks to
  every source before including it in the generated .sh script:

    a) Official first-party domain - the source MUST be the software's OWN official
       domain (e.g. google.com for Chrome, microsoft.com for Edge/VS Code/PS/.NET,
       docker.com for Docker, postgresql.org for PostgreSQL/PGDG/pgAdmin, dbeaver.io
       for DBeaver, zoom.us for Zoom, discord.com for Discord, parsec.app for Parsec,
       gitkraken.com for GitKraken, rclone.org for rclone, anaconda.com for Miniconda,
       languagetool.org for LanguageTool, brew.sh for Homebrew, nodejs.org for
       Node.js, protonvpn.com for Proton VPN, anydesk.com for AnyDesk, winehq.org for
       WineHQ, virtualbox.org for Oracle VirtualBox, realvnc.com for RealVNC Viewer,
       apple.com for anything Apple ships).

    b) HTTPS mandatory - all downloads, taps, and key URLs MUST use HTTPS. Reject
       any source that is HTTP-only or redirects to HTTP.

    c) Checksum verification - prefer Homebrew Cask/formula, because every cask
       carries the upstream URL AND a sha256 that brew verifies before installing, and
       the cask definitions are reviewed in a public repo. A THIRD-PARTY TAP is only
       acceptable from the vendor's own GitHub organisation. For a direct .dmg/.pkg
       download, the vendor must serve it over HTTPS from its own domain; macOS then
       checks the developer's Apple code signature and notarisation on first launch.

    d) No curl-pipe-bash from untrusted domains - `curl ... | bash` is acceptable
       ONLY from absolutely trusted first-party domains (e.g. rclone.org). Never pipe
       to bash from third-party sites, shortened URLs, or redirect services.

    e) Manual downloads (login-gated) - the script MUST print the EXACT official URL
       the user should visit, not a search suggestion or a third-party mirror. The
       URL must resolve to the vendor's own domain.

    f) SpotPlayer - this app is distributed from spotplayer.ir, a domain that cannot
       be verified as a trusted first-party source by the standards above. It MUST
       remain in the MANUAL section and the user MUST be warned that they are
       responsible for verifying the download's authenticity before installing it.

    g) Any source that cannot satisfy (a)-(c) MUST NOT be included in the automated
       section. Move it to MANUAL with a clear warning about verifying authenticity.
       Include a prominent "TRUSTED SOURCES GUARANTEE" comment block at the top of
       the generated script, after the header comment, stating that every source
       meets these criteria.

SOURCE-OF-PACKAGE PRIORITY (per the user's rule)
  0. THE VENDOR'S OWN macOS BUILD, whenever one exists. This is the rule that makes the
     macOS edition different from the Linux one: Microsoft Office, Adobe Creative Cloud,
     WhatsApp, AutoCAD, Logic Pro and hundreds more ship real Mac applications, so the
     manifest leads with them at competency 100 and only then lists substitutes.
  1. Homebrew CASK (GUI apps) - one token for every macOS version and both architectures.
  2. Homebrew FORMULA (CLI/dev tools) or the Mac App Store via `mas` for Store-only apps.
  3. A direct vendor .dmg/.pkg download, or the manual download-page flow, only where

  Apps whose counterpart SHIPS WITH macOS use method "builtin" and install nothing.
  Always install the LATEST available version.

WINE (WINDOWS EMULATOR) - OPTIONAL, FOR NON-CROSS-PLATFORM APPS
  * Gated by the setup question "Install the non-cross-platform Windows applications
    under the Windows emulator (wine) too?" (MIGRATE_WINE_NONCROSS=yes). The generator
    emits a `wine_app "<name>" "<windowsInstaller-url>"` call for every DETECTED app that
    is a Win32 desktop app with no native "Available on macOS" build (e.g. Notepad++,
    WinRAR, IDM).
  * 32-BIT (i386) APPS CANNOT RUN AT ALL. macOS removed the 32-bit runtime in Catalina
    (10.15), so there is no win32-prefix escape hatch as there is on Linux. is_32bit_pe
    inspects the installer UP FRONT (PE header, or the MSI "Template" summary field) and,
    when it is 32-bit x86, the app is reported as MANUAL with the actual answer -
    CrossOver (which ships its own 32-bit layer) or a Windows VM (Parallels / VMware
    Fusion / UTM) - instead of letting wine fail later with a cryptic c0000135. 64-bit
    apps use the default win64 prefix and are unaffected.
  * CRASH-BUT-INSTALLED RESCUE: under wine an installer commonly exits non-zero by crashing
    on a FINAL step (a missing Wine Gecko / HTML ad pane, a "run now" launch, etc.) AFTER it
    has already written the program. So when wine_run_installer returns non-zero, the engine
    checks wine_app_installed (a real Start-Menu .lnk, or an app folder under Program Files
    beyond the wine defaults); if found it marks the app UNVERIFIED (still ledgered, with
    launchers created) instead of FAILED, so these apps are not lost. A genuine failure (no
    files written) still reports FAILED with the reason + reproduce command. (Apps that
    install only into per-user AppData and create no shortcut are not auto-detected.)
  * Install Wine from Homebrew Cask ("wine-stable"); on Apple Silicon install Rosetta 2
    first, because Wine is an x86_64 build. Then, per app:
      - If the manifest entry has a "windowsInstaller" URL (a trusted, official, DIRECT
        installer link; currently Notepad++ and WinRAR), DOWNLOAD it and run it under
        Wine silently (.exe -> /S, .msi -> msiexec /i /qn, .bat -> cmd /c).
      - Otherwise ASK for the installer path ('installer path'/skip/skip all; full path
        or relative to ~/Downloads; any extension .exe/.msi/.bat/...).
  * NON-BLOCKING INSTALL (wine_run_installer): the installer is run in the BACKGROUND with
    its output redirected to a LOG FILE -- never through a live "tee" pipe. Many installers
    auto-launch the app (or leave a tray/updater) the instant they finish; such a process
    inherits the console pipe and would hold it open and HANG the whole script. The engine
    waits for the installer to exit on its own (bounded by MIGRATE_WINE_INSTALL_TIMEOUT,
    default 600s; on timeout it force-stops it), then runs `wineserver -k` to terminate
    every remaining Windows process in this per-app prefix so wine fully exits and the
    script continues. A one-time NOTE tells the user to close any "Setup finished / Run now"
    window that pops up. Because each app has its own prefix and the prefix is killed after
    each install, wine never hits Windows' "another setup is already running" msiexec-mutex
    error (that mutex is per-prefix, not host-wide, and is cleared by wineserver -k).
  * Each app gets its OWN isolated Wine prefix (~/.local/share/wineprefixes/<slug>),
    created/owned by $SUDO_USER; apply a winetricks font baseline (corefonts) best-effort.
  * IDEMPOTENT: if a Start-Menu .lnk for the app already exists in its prefix (it was
    installed on a previous run), wine_app does NOT blindly re-install. Re-installing into
    the same persistent prefix re-applies the app's setup on top of itself and can COMPOUND
    its saved UI metrics (e.g. IDM's toolbar/font), making the window grow on every run.
    The DPI itself is ALWAYS an ABSOLUTE set to 240 (never current*2.5), so it does not
    accumulate; the growth came purely from re-launching + re-applying the FIRST-INSTALL
    appearance setup on every run. Behaviour:
      - MIGRATE_UPDATE_EXISTING != yes -> SKIP the re-install (the app is already present).
      - MIGRATE_UPDATE_EXISTING  = yes -> UPGRADE IN PLACE: keep the prefix (so the user's
        data/settings are preserved -- an upgrade must NOT wipe them), refresh only the
        program binaries, and do NOT redo the first-install appearance setup. The base DPI
        write, the WINE_CFG_DPI/WINE_CFG_DESKTOP/WINE_APPEARANCE_ALL state, and the
        interactive wine_tune_appearance pass run on FIRST INSTALL ONLY; on upgrades the
        existing appearance is left exactly as the user has it, so it can never bloat.
    To reset a prefix already bloated by past runs, delete it once (it then reinstalls clean).
  * After install, force Wine DPI to 240 (LogPixels = 0xF0, i.e. 2.5x of the 96 default)
    via `wine reg add`, run as $SUDO_USER, so fonts/UI are readable. Generate .desktop
    launchers for any Start-Menu .lnk shortcuts the installer created.
  * FIRST-LAUNCH APPEARANCE TUNING (interactive; `wine_tune_appearance`, only with a tty):
    immediately after a successful install, with one blank line first, print in PURPLE
    "Now we launch the installed <app> for the first time for testing", LAUNCH the app
    (its main Start-Menu .lnk, via run_wine_gui so DISPLAY/Wayland is forwarded), then in
    PURPLE "According to what you see for the appearance of the app, adjust the following
    visual settings or press enter to leave the default values:". Then prompt for EACH
    adjustable visual factor in the form
      "enter new value for <param> in the format <fmt> (Current:<value reproducing the
       present look>) or enter to leave it unchanged"
    The factors are: font scaling (DPI) [whole number 96-480; Current:240] and window
    size [(width,height) or "off"; Current:off]. Each value is VALIDATED before use;
    an invalid entry prints a RED error and re-asks the SAME prompt. Then CLOSE the app
    (wineserver -k), apply the changes (LogPixels + Wine\Explorer virtual-desktop regkeys),
    RE-LAUNCH it, and ask in PURPLE
      'Is the current appearance what you would expect? "a" applies same configurations
       to all upcoming wine installations. (y=yes / a=yes all / r=start over)'
    r = start over (re-collect values in a loop, ending only on y or a); a = remember the
    values and apply them SILENTLY to every later wine install (no launch/prompt);
    y = accept. Then close the app and continue the script. No tty -> skip tuning, keep
    the 2.5x default. STRICTLY additive: nothing else in the wine flow changes.
  * Wine is INDEPENDENT of the alternatives count: with alternatives > 0 the native
    alternative(s) AND the Wine app are installed; with 0, only the Wine app is.
  * The native macOS alternatives (e.g. notepadqq/geany for Notepad++; p7zip for WinRAR)
    are still installed via the normal alternatives path. The windowsInstaller URLs are
    version-pinned, so they need an occasional refresh (a 404 falls back to the prompt).

FONT IMPORT (INTERACTIVE, AFTER POST-INSTALL, BEFORE MANUAL)

  After all automated installs complete and post-install services are configured,
  the script prompts the user to optionally import fonts from a local directory.
  This runs BEFORE the manual/login-gated downloads (section 11).

  Behaviour:
    * Print a banner explaining what the step does and which file types are
      supported.
    * Loop: ask the user for a directory path (or "skip") via /dev/tty.
    * Validate the path: must exist and be readable. If not, show a clear error
      and reprompt.
    * Recursively find all font files in the directory. Supported extensions
      (case-insensitive):
        .ttf .otf .ttc .woff .woff2 .pfa .pfb .afm .pfm .dfont .otb .bdf .pcf
        .gsf .otc .abf .chr .fnt .mxf
      These cover Windows TrueType/OpenType/Web fonts, macOS dfont, and macOS
      bitmap/pcf/bdf fonts.
    * If no matching files are found, warn the user and reprompt.
    * Copy each font file to /usr/local/share/fonts/user-import/ (create the
      directory first). Skip files that already exist with the same byte size
      (idempotent - safe to re-run).
    * If an individual file cannot be copied (permission denied, read error),
      warn about that file and continue with the rest. Track counts: total found,
      successfully installed, and failed.
    * After copying, run `fc-cache -fv` on the font directory to refresh the
      system font cache so applications (including Wine) see the new fonts
      immediately.
    * Log per-file status (installed / already present / copy-failed) to the
      install log via the script's `info`/`warn` functions.
    * Record the overall step as OK (with count summary), SKIP (user chose skip
      or no tty), or FAIL via the existing `mark_ok`/`mark_skip`/`mark_fail`
      mechanism.

  Error handling built in:
    * Directory doesn't exist          → print error, reprompt
    * Directory not readable           → print error, reprompt
    * No font files in directory       → warn + reprompt
    * Permission denied on a file      → skip that file, continue
    * No tty (non-interactive env)     → skip the entire step silently
    * Empty input or "skip"            → skip the entire step, record as SKIP

  The function name is `_install_fonts_from_dir` and it is invoked via:
    step "Import user fonts from directory" _install_fonts_from_dir

POST-INSTALL
  Enable services (ssh, postgresql, docker) and add the invoking $SUDO_USER to the
  docker group. Recommend a reboot at the end (kernel modules, group changes).


 PART D - SETTINGS MIGRATION SPEC
 (files: C_detect_windows_settings.ps1, <Target OS>/apply_settings.sh)

GOAL
  Extract ~26 categories of common Windows user settings, write them to
  C_windows_configs.csv (in the documents/ directory), then apply them on the target
  macOS version using the universal apply_settings.sh. CATEGORIES 1-6 below are the
  original core set; CATEGORIES 7+ (mouse, accessibility, keyboard repeat, time,
  locale, proxy, touchpad, appearance, default apps, hosts, printers, static net,
  WiFi, firewall) and the POST-INSTALL items (shortcuts, startup, services,
  scheduled tasks, SSH, Contacts, wallpaper) are documented in the CURRENT
  ARCHITECTURE block at the top of this file and in the apply functions. Every CSV
  row carries Phase (pre|post) and Scope (User|System) columns; apply_settings.sh is
  invoked as `apply_settings.sh pre` then `apply_settings.sh post`.

  NOTE - SINGLE-FILE DESIGN: the apply functions and the dispatch table were
  formerly split into a separate settings_config.sh that apply_settings.sh sourced.
  They are now MERGED into apply_settings.sh, which is fully self-contained. Do NOT
  regenerate a separate settings_config.sh.

  NOTE - SCOPE ON macOS (hard requirement): macOS splits settings into machine-wide
  ones and per-user preference domains, and each must be written the RIGHT way.
  Machine-wide (systemsetup, pmset, networksetup, pfctl, socketfilterfw, lpadmin,
  /etc/hosts, LaunchDaemons) already applies to every account. Per-user preferences
  MUST be written with `defaults` AS THE LOGGED-IN USER through the run_as_user helper,
  which wraps the call in `launchctl asuser <uid> sudo -u <user>` so it lands in the
  real Aqua session. NEVER run `defaults write` as root for a user key - that only
  changes root's own domain and reaches no real user (the exact mistake the Linux
  edition avoided with system-wide dconf defaults).

DIRECTORY LAYOUT (settings-migration files)
  Migrate to macOS/
    C_detect_windows_settings.ps1         <- PowerShell script run on Windows
    C_windows_configs.csv                  <- produced by the PS1, copied here
    <Target OS>/
        apply_settings.sh                <- self-contained runner: the _apply_*
                                            functions + SETTINGS_DISPATCH table +
                                            the CSV-reading runner, all in ONE file

WORKFLOW (settings migration)
  Step S1  Run C_detect_windows_settings.ps1 on the Windows machine:
               powershell -ExecutionPolicy Bypass -File C_detect_windows_settings.ps1
           This produces C_windows_configs.csv in the same (Migrate to macOS/) folder.
  Step S2  Copy C_windows_configs.csv to the Migrate to macOS/ directory on the
           Mac.
  Step S3  On the target Mac, cd into the distro directory and run:
               sudo ./apply_settings.sh
           It reads ../C_windows_configs.csv and calls the appropriate built-in
           _apply_* function for each row (no external file is sourced).

CATEGORY 1 - POWER SETTINGS (lid-close action)

  Windows extract (C_detect_windows_settings.ps1):
    * Reads active power plan GUID from WMI (Win32_PowerPlan).
    * Queries Win32_PowerSettingDataIndex for the lid-close setting
      (GUID 5ca673a8-0e47-b2fd-5cb6-ef6e1e0a9c3e) on both AC and DC.
    * Registry fallback: HKLM\...\Power\User\PowerSchemes\...\ACSettingIndex / DCSettingIndex.
    * Produces CSV rows:
        Power | lid_close_on_ac      | <action>
        Power | lid_close_on_battery | <action>
      where <action> ∈ {do nothing, sleep, hibernate, shut down, turn off display}.

  macOS apply (apply_settings.sh → _apply_power_lid):
    * Maps Windows action to logind action:
        do nothing → ignore, sleep → suspend, hibernate → hibernate,
        shut down → poweroff, turn off display → lock.
    * Writes HandleLidSwitch= and HandleLidSwitchExternalPower= in
      /etc/systemd/logind.conf.
    * Also writes a drop-in file /etc/systemd/logind.conf.d/50-migrate-lid.conf
      (survives distro upgrades).
    * Restarts systemd-logind.
    * Prints structured output: [OK] / [ERROR] / [INFO] per sub-step.

CATEGORY 2 - DISPLAY RESOLUTION & SCALING

  Windows extract:
    * Resolution from CIM_VideoController (CurrentHorizontalResolution ×
      CurrentVerticalResolution), e.g. "1920x1080".
    * Scaling from HKCU\Control Panel\Desktop\LogPixels or AppliedDPI,
      e.g. "125%" or "100%".
    * Produces CSV rows:
        Display | resolution | <WxH>
        Display | scaling    | <percentage>%

  macOS apply:
    * Resolution: `displayplacer "id:<persistent id> res:<WxH>"` when the mode exists
      (displayplacer is offered on demand; macOS ships no resolution CLI of its own).
    * Scaling: REPORTED, not applied. macOS has no text-scaling factor - the whole UI is
      scaled by choosing a HiDPI "looks like" resolution per display, which is a manual
      choice in System Settings > Displays. Emit a manual note carrying the Windows %.

CATEGORY 3 - KEYBOARD LAYOUT & SHORTCUTS

  Windows extract:
    * Current culture from [System.Globalization.CultureInfo]::CurrentCulture.
    * Input methods from Get-WinUserLanguageList → LanguageTag list.
    * Notes standard Windows shortcuts (Win+E, Win+L, Win+Shift+S, etc.).
    * Produces CSV rows:
        Keyboard | layout         | <culture string>
        Keyboard | shortcuts_note | <semicolon-separated shortcut list>

  macOS apply:
    * Maps Windows language tags to macOS input sources (en-US→"U.S.", fa-IR→"Persian").
    * Writes com.apple.HIToolbox AppleEnabledInputSources as an array of
      {InputSourceKind="Keyboard Layout"; "KeyboardLayout ID"; "KeyboardLayout Name"}
      dictionaries. Takes effect after a log out / log in.
    * Key repeat: Windows reports milliseconds; macOS counts 15 ms ticks and LOWER is
      FASTER, so convert into NSGlobalDomain InitialKeyRepeat / KeyRepeat and clamp.
    * NumLock: not applicable - Mac keyboards have no Num Lock key. Log a note.
    * Shortcuts: prints an informational reference (Ctrl→Command mapping table).

CATEGORY 4 - DISABLE TELEMETRY; LIMIT LOCATION

  Windows extract:
    * Telemetry level from HKLM\...\DataCollection\AllowTelemetry
      (0=Security, 1=Basic, 2=Enhanced, 3=Full).
    * Location consent from HKLM\...\CapabilityAccessManager\ConsentStore\location.
    * Produces CSV rows:
        Telemetry | telemetry_level  | <level>
        Telemetry | location_service | <enabled/disabled>

  macOS apply (telemetry):
    * /Library/Application Support/CrashReporter/DiagnosticMessagesHistory.plist
      AutoSubmit + ThirdPartyDataSubmit -> false (system-wide, needs root).
    * com.apple.assistant.support "Siri Data Sharing Opt-In Status" -> 2 (opted out).
    * com.apple.AdLib allowApplePersonalizedAdvertising -> false.

  macOS apply (location):
    * /var/db/locationd/.../com.apple.locationd LocationServicesEnabled -> 0, then
      `launchctl kickstart -k system/com.apple.locationd`.
    * System Integrity Protection guards this plist on recent releases, so treat a
      failure as EXPECTED: report a manual note pointing at System Settings >
      Privacy & Security > Location Services rather than marking it failed.

CATEGORY 5 - AUTO-UPDATE SERVICE FILES

  Windows extract:
    * Placeholder flag (no extractable Windows equivalent).
    * Produces CSV row:
        AutoUpdate | install_service_files | system_update

  macOS apply (_apply_auto_update_services):
    * Copies system_update.service and system_update.timer from
      <repo_root>/Scheduled systemd Automatic Update/Debian/service files/
      to /etc/systemd/system/.
    * systemctl daemon-reload.
    * systemctl enable --now system_update.timer.

CATEGORY 6 - LOCK SCREEN TIMEOUT (idle → lock/blank)

  Windows extract:
    * Primary signal: a SECURE screen saver - HKCU\Control Panel\Desktop with
      ScreenSaveActive=1, ScreenSaverIsSecure=1, ScreenSaveTimeOut=<seconds>.
    * Fallback: power "turn off display after" (SUB_VIDEO 7516b95f...\VIDEOIDLE
      3c0bc021...) ACSettingIndex (seconds) under PowerSchemes.
    * Emit minutes, or "never" when nothing locks the screen (so macOS disables the
      lock/blank too - mirroring a Windows box with no lock-screen timeout).
    * Produces CSV row:
        Screen | lock_screen_timeout | <N> min   (or "never")

  macOS apply (_apply_lock_screen_timeout - ALL USERS via _dconf_system_set):
    * "never"/0  -> org/gnome/desktop/session idle-delay uint32 0 (never blank),
                    org/gnome/desktop/screensaver lock-enabled false,
                    org/gnome/desktop/screensaver idle-activation-enabled false.
    * "<N> min"  -> session idle-delay uint32 <N*60>, screensaver lock-enabled true,
                    screensaver lock-delay uint32 0.

CATEGORY 7 - MOUSE & TOUCHPAD
  Windows: HKCU\Control Panel\Mouse (MouseSensitivity 1..20, MouseSpeed accel flag,
  SwapMouseButtons, DoubleClickSpeed) + Cursors\CursorBaseSize; PrecisionTouchPad
  (TapsEnabled, ScrollDirection). Rows: Mouse|mouse_size/speed/accel/swap/dblclick,
  Touchpad|touchpad_tap/natural.
  macOS: org.gnome.desktop.peripherals.mouse speed(-1..1)/accel-profile/left-handed/
  double-click; interface cursor-size; peripherals.touchpad tap-to-click/natural-scroll.

CATEGORY 8 - ACCESSIBILITY
  Windows: the \Flags bitmask (bit0=on) of StickyKeys / Keyboard Response (slow keys) /
  MouseKeys / HighContrast, plus ScreenMagnifier RunningState. Rows: Accessibility|
  a11y_stickykeys/slowkeys/mousekeys/highcontrast/magnifier ('true'/'false').
  macOS: org.gnome.desktop.a11y.keyboard stickykeys/slowkeys/mousekeys-enable,
  a11y.interface high-contrast, a11y.applications screen-magnifier-enabled.

CATEGORY 9 - KEYBOARD REPEAT + NUMLOCK
  Windows: HKCU\Control Panel\Keyboard KeyboardDelay(0..3->250..1000ms),
  KeyboardSpeed(0..31 cps -> ms between repeats), InitialKeyboardIndicators NumLock bit.
  Rows: Keyboard|key_repeat_delay/key_repeat_rate/numlock.
  macOS: org.gnome.desktop.peripherals.keyboard delay/repeat-interval (uint32 ms)/
  numlock-state.

CATEGORY 10 - TIME (TIMEZONE + NTP) [Scope=System]
  Windows: TimeZoneInfo.Local.Id -> IANA id (TryConvertWindowsIdToIanaId on PS7, else a
  built-in map); W32Time\Parameters NtpServer (only if NON-Microsoft, else pool.ntp.org).
  Rows: Time|timezone, Time|ntp_server.
  macOS: timedatectl set-timezone; systemd-timesyncd NTP=; timedatectl set-ntp true.

CATEGORY 10b - DESKTOP/SYSTEM EXTRAS
  Locale [System]:   HKCU\...\International LocaleName -> LANG=xx_XX.UTF-8 (localectl).
  Proxy:             WinINET Internet Settings (AutoConfigURL / ProxyServer) ->
                     org.gnome.system.proxy mode/host/port/autoconfig-url.
  Appearance:        Themes\Personalize AppsUseLightTheme -> interface color-scheme;
                     DWM AccentColor -> nearest GNOME accent (GNOME 47+); blue-light
                     reduction blob -> settings-daemon color night-light-enabled.
  DefaultApps [post]: https UserChoice ProgId -> default_browser (xdg-settings, applied
                     post-install once the browser exists).
  Hosts [System]:    custom (non-boilerplate) /etc/hosts entries -> merged into macOS
                     /etc/hosts.
  Printers [System]: network/shared printers (IP_/WSD/http ports) -> CUPS lpadmin
                     (best-effort). Local USB printer drivers are not portable.
  NetConfig [System]: manual static IP/DNS adapters -> recorded as a MANUAL NOTE only
                     (never auto-applied, so migration cannot break the user's network).
  Power sleep [System]: STANDBYIDLE AC/DC -> power sleep-inactive-ac/battery-timeout.

CATEGORY 11 - WIFI  [Scope=System]
  Windows: `netsh wlan show profiles` + `... profile name=<n> key=clear` -> SSID, auth
  (open|wpa), and the pre-shared key. The key is encrypted with the TRANSFER PASSWORD
  (OpenSSL AES-256-CBC/PBKDF2, base64) so it travels safely; with no password/openssl,
  profiles are exported WITHOUT passwords. Fields pipe-packed: ssid|auth|secret|sectype
  (sectype = enc|none). Row: Wifi|wifi_profile.
  macOS (apply_wifi): resolve the Wi-Fi device from `networksetup -listallhardwareports`,
  then `networksetup -addpreferredwirelessnetworkatindex <dev> <ssid> 0 <security>
  [password]`, mapping the Windows auth string to OPEN|WEP|WPA|WPA2|WPA3. Encrypted keys
  are decrypted with MIGRATE_XFER_PWD first, and the key is also written to
  /Library/Keychains/System.keychain with `security add-generic-password` so the Mac
  auto-joins. Re-adding an existing SSID is how its stored password is updated.

CATEGORY 12 - FIREWALL  [Scope=System]
  Windows: Get-NetFirewallRule + PortFilter/ApplicationFilter/ServiceFilter. Fields
  pipe-packed: name|direction|action|enabled|proto|localport|remoteport|program|service.
  Row: Firewall|fw_rule.
  macOS: PORT rules -> one pf anchor. Buffer every rule as a `pass|block drop quick
  in|out proto tcp|udp from any to any port N[:M]` line, write them all to
  /etc/pf.anchors/migrate_to_macos, append the `anchor` + `load anchor` pair to
  /etc/pf.conf once (idempotent, with a .bak), validate with `pfctl -n -f /etc/pf.conf`
  and only then load. Service-keyword ports (PlayToDiscovery->3702, mDNS->5353, ...) are
  translated or skipped-with-a-note. A rule bound to a specific PROGRAM (or an "any port"
  rule too broad for a port firewall) is recreated with the macOS Application Firewall -
  `socketfilterfw --add <app> --blockapp|--unblockapp` - after resolving the Windows exe
  name to an installed .app. That firewall is program-scoped BY DESIGN, so on macOS this
  is the native shape of the rule and needs no third-party tool.

APPLY_SETTINGS.SH STRUCTURE (single self-contained file)
  apply_settings.sh holds EVERYTHING - there is no separate settings_config.sh.
  Generate it as one file containing, in order:

  A) Apply-function block (formerly settings_config.sh):
    * Output helpers:
        _cfg_ok()    - green  [OK]    to stdout
        _cfg_info()  - dim    [INFO]  to stdout
        _cfg_error() - red    [ERROR] to stderr
    * The _dconf_system_set SCHEMA KEY GVARIANT helper (ALL-USERS mechanism): ensures
      dconf-cli; ensures /etc/dconf/profile/user has "system-db:local"; writes ONE
      deterministic keyfile per (schema,key) under /etc/dconf/db/local.d (rewritten
      wholesale => idempotent); runs `dconf update`. Used by the scaling, location and
      lock-screen functions so they reach every user, not just root.
    * One _apply_* function per config key (see dispatch table below). Each takes
      the WindowsValue column as argument $1 and returns 0 on success, non-zero on
      failure. Special functions: _apply_power_lid takes a second argument (logind
      key); _apply_keyboard_layout takes a second argument (input languages string).
      _apply_lock_screen_timeout parses "<N> min"/"never" and sets idle-delay +
      screensaver lock keys via _dconf_system_set.
    * The SETTINGS_DISPATCH associative array:
        ["Category|ConfigKey"]="function_name"
      CRITICAL: associative-array literals need [key]=value with NO spaces around
      '='. Writing `["k"]  ="v"` silently produces broken keys like `["k"]` and the
      runner then matches NOTHING and applies nothing. Keep `[key]="value"` tight.
    * The POWER_LOGIND_KEY associative array for lid-close key mapping.

  B) Runner block:
    * require_root (verify EUID 0; exit otherwise).
    * Read ../C_windows_configs.csv from the parent Migrate to macOS/ directory.
    * Parse the CSV header to get column indices (robust against reordering).
    * Iterate each data row, look up the dispatch key, call the function.
    * Track OK/FAIL/INFO and print a summary at the end.
    * Exit with code 1 if any step failed.
    * Must NOT use set -o pipefail (causes silent aborts).
    * Must use `rc=0; func || rc=$?` pattern, not set +e/set -e dance.
    * Does NOT source any external file (it already contains the functions/table).

  ROBUSTNESS REQUIREMENTS (regressions found in real runs - do NOT reintroduce):
    * QUOTE-AWARE CSV PARSING: parse each data row with a real CSV parser
      (parse_csv_line -> CSV_FIELDS) that honours double-quoted fields containing
      commas and "" escapes, and strips a trailing CR (PowerShell writes CRLF). The
      naive `cut -d,` approach mis-splits fields like the keyboard "en-US, fa"
      (dropping the 2nd language) and truncates any Notes/value containing a comma.
    * LOCALE-PROOF NUMBERS for dconf: format the scaling float with `LC_ALL=C awk`
      so the decimal separator is a DOT. On comma-locales (fa_IR/de_DE) awk prints
      "1,50", an INVALID GVariant double; `dconf update` then fails to compile the
      whole /etc/dconf/db/local.d and the failure CASCADES to every other dconf key.
      Do not emit bare integers for double keys either (use 1.50/2.00, not 1/2).
    * dconf CLEANUP-ON-FAILURE: if `dconf update` fails after writing a keyfile,
      remove that keyfile and recompile, so one bad key cannot poison later keys.
    * KEYBOARD FALLBACK: localectl can fail (headless VM / no systemd-localed / DBus).
      When it does, write /etc/default/keyboard (XKBLAYOUT=) and
      /etc/X11/xorg.conf.d/00-keyboard.conf directly (system-wide). Count the step OK
      if EITHER localectl OR the file-writes succeed. setxkbmap is best-effort for the
      current session only and must NOT make the step fail (Wayland/headless/root).

OUTPUT FORMAT (from the built-in _apply_* functions in apply_settings.sh)
  Every _apply_* function must print structured output so the user sees exactly
  what succeeded and what failed. Example:

    [INFO]  Windows 'sleep' → logind HandleLidSwitch=suspend
    [OK]    removed old HandleLidSwitch= from logind.conf
    [OK]    wrote HandleLidSwitch=suspend → /etc/systemd/logind.conf
    [OK]    wrote /etc/systemd/logind.conf.d/50-migrate-lid.conf
    [OK]    restarted systemd-logind

    [INFO]  disabling macOS telemetry...
    [OK]    disabled & masked: whoopsie
    [INFO]  not present: apport
    [OK]    disabled ESM hook
    [OK]    purged: ubuntu-report

    [ERROR] displayplacer could not set 2560x1440 (the mode may be unsupported)


===============================================================================
 PART E - DEVICE DRIVER MIGRATION SPEC
 (files: A_detect_installed_drivers.ps1, A_installed_windows_drivers.csv,
         <Target OS>/install_device_drivers.sh)
===============================================================================

GOAL
  Inventory EVERY device driver on the Windows PC and rate how each device is
  handled on macOS; then, on the target Mac, install the macOS driver
  for every device that needs one beyond the in-box kernel - downloading from the
  manufacturer where required.

KEY PRINCIPLE (do not violate)
  On macOS, the AUTHORITATIVE source of truth for drivers is the LIVE hardware
  (lspci/lsusb/lscpu/DMI on the target), NOT the Windows device names - those don't
  map cleanly to macOS modules. The CSV is a cross-reference/report; the installer
  detects hardware itself and installs accordingly. Absent hardware => "skipped",
  never "failed".


PART E1 - POWERSHELL DRIVER INVENTORY  (A_detect_installed_drivers.ps1)

  PARAMETERS
    -OutputPath <path>           default: A_installed_windows_drivers.csv beside script
    -IncludeVirtualDevices       switch, default off (keep ROOT\/SW\/SWD\/SWC\ etc.)
    -IncludeMicrosoftInbox       switch, default off (keep generic MS in-box drivers)

  COLLECTION (machine-derived; read live, never hand-authored)
    Enumerate Get-CimInstance Win32_PnPSignedDriver (fall back to Get-WmiObject).
    Guard EVERY property access with a Safe-Property try/catch (DeviceName,
    DeviceClass, Manufacturer, DriverVersion, DriverDate, DriverProviderName,
    HardWareID, DeviceID) so missing properties never throw.

  FILTERING (noise removal)
    Parse the bus prefix from the Hardware ID (PCI / USB / ACPI / HID / BTHENUM /
    ROOT / SW / SWD / SWC ...). By default DROP virtual/software buses
    (ROOT, SW, SWD, SWC, STORAGE, UMB, VMS, or empty) unless -IncludeVirtualDevices.
    By default also drop generic Microsoft in-box drivers on non-PCI/USB buses
    unless -IncludeMicrosoftInbox. De-duplicate by (Device Name + Hardware ID).

  THE 12 CSV COLUMNS (exact header text, in this order)
    Device Name            (machine)
    Device Class           (machine: DISPLAY, NET, BLUETOOTH, PRINTER, ...)
    Manufacturer           (machine)
    Driver Version         (machine)
    Driver Date            (machine: yyyy-MM-dd)
    Driver Provider        (machine)
    Hardware ID            (machine: PCI\VEN_xxxx&DEV_xxxx / USB\VID_xxxx&PID_xxxx)
    macOS Driver Status    (curated flags - see below)
    macOS Driver / Module  (curated: kernel module or package name)
    Vendor Download        (curated: manufacturer macOS page; only when a vendor
                            download is actually needed)
    Notes                  (curated)
    Must install on macOS  (DERIVED in code: yes | no)

  macOS DRIVER STATUS FLAGS - a cell may hold several, ALWAYS in this order:
    In-OS ; Generic Driver ; Vendor Driver ; Not Supported ; Not Applicable ; Needs Review

  CLASSIFICATION ($DriverKB) - the single place curated data lives
    An ordered rule array; first matching rule wins (specific before generic).
    Match on: Device Class (regex), the PCI/USB VENDOR ID extracted from the
    Hardware ID (VEN_/VID_ -> 4 hex, e.g. 10DE=NVIDIA, 8086=Intel, 1002=AMD,
    10EC=Realtek, 14E4=Broadcom, 168C=Qualcomm Atheros, 14C3=MediaTek), the Device
    Name (regex), and optionally the bus prefix (e.g. BTHENUM). Each rule yields the
    Status flags, the macOS Driver/Module, the Vendor Download URL and a Note.
    Representative mappings (research current modules/packages at generation time):
      * NVIDIA GPU (Display, 10DE)   -> Not Supported (no macOS driver at all)
      * AMD GPU (Display, 1002)      -> In-OS AMDRadeonX6000 family
      * Intel GPU (Display, 8086)    -> In-OS AppleIntelGraphics (Intel Macs)
      * Any Wi-Fi (Net)              -> In-OS IO80211Family (a PC card cannot move to a Mac)
      * Realtek USB Wi-Fi (Net,0BDA) -> Vendor Driver (patchy; the Mac's own radio is better)
      * Ethernet (Net)               -> In-OS AppleEthernet / class-compliant USB
      * Bluetooth                    -> In-OS IOBluetoothFamily
      * HD Audio                     -> In-OS AppleHDA / USB Audio Class + Core Audio
      * Webcam (UVC)                 -> In-OS CoreMediaIO UVC
      * NVMe / AHCI                  -> In-OS IONVMeFamily / IOAHCIFamily
      * CPU (Processor)              -> Not Applicable (microcode ships with macOS)
      * HP printer/scanner           -> Generic AirPrint + Vendor HP Easy Start
      * Other printer                -> Generic AirPrint / IPP Everywhere via CUPS
      * Fingerprint (Biometric)      -> Not Supported (Touch ID is Apple hardware)
      * USB-serial FTDI/CH34x/CP210x/PL2303 -> Vendor Driver (the classic real case)
      * Wacom tablet (056A)          -> Vendor Driver wacom-tablet
      * System firmware/UEFI         -> Not Applicable (Apple Software Update)
      * Paired Bluetooth periph (BTHENUM) / monitors -> Not Applicable
    Unknown devices => Status "Needs Review", Driver "check System Information /
    system_profiler SPUSBDataType on the Mac".

  "MUST INSTALL ON macOS" (computed, not hand-set)
    yes ONLY when the Status contains "Vendor Driver" - i.e. a vendor kext / DriverKit
    system extension / vendor installer is genuinely required. "Not Supported" is NOT a
    yes: there is nothing to install for hardware macOS cannot drive at all. Everything
    else (In-OS / Generic Driver / Not Applicable) is no.

  OUTPUT + SUMMARY
    Export the 12 columns to CSV (UTF-8, -NoTypeInformation). Print totals: devices
    listed, "Must install" count, and a breakdown by status category.


PART E2 - macOS DRIVER STAGE  (<Target OS>/install_device_drivers.sh)

  EXECUTION MODEL  (identical conventions to install_must_have_software.sh)
    * Bash, run as ROOT. set -uo pipefail. Never abort on one failure; record
      OK/FAIL/SKIP and print a summary.
    * SAME clean-UI machinery: save the terminal on fd 3 (exec 3>&1 4>&2), send all
      command noise to a log (exec >>"$LOG" 2>&1), print only curated "==> step"
      lines + a live spinner; Homebrew prints its own progress. TWO logs:
      driver-install.log (verbose) and driver-install-results.log (one line/step).
    * Auto-detect the macOS release (sw_vers) and ARCH (uname -m + proc_translated) -
      nothing hard-coded.

  LIVE HARDWARE DETECTION (authoritative)
    Capture once with the tools macOS already has: system_profiler SPHardwareDataType,
    lsusb, CPU vendor (/proc/cpuinfo), DMI sys_vendor/product_name. Derive boolean
    presence flags (NVIDIA/AMD/Intel GPU; Realtek/Broadcom NIC & USB Wi-Fi; HP;
    fingerprint vendor IDs 06cb/27c6/138a/08ff/1c7a; printer) by grepping lspci/lsusb.

  CROSS-REFERENCE (optional)
    If ../A_installed_windows_drivers.csv exists, list the device names whose last
    field is "yes" (rows flagged "Must install on macOS"). Robust against embedded
    quotes and the CRLF line endings PowerShell writes. Informational only.

  WHAT IT INSTALLS (gate every step on a detection flag)
    1. Base: nothing to install - macOS ships the drivers and the diagnostic tools
       (system_profiler, kmutil, systemextensionsctl, networksetup) itself. Warn that a
       third-party kernel extension must be APPROVED in System Settings > Privacy &
       Security (and on Apple Silicon needs Reduced Security in Recovery) before macOS
       will load it.
    2. GPU: nothing to install. Apple ships the driver in macOS. Report the chipset
       from `system_profiler SPDisplaysDataType`. NVIDIA is NOT supported on macOS at
       all (web drivers ended with High Sierra; Apple Silicon has no PCIe GPU support);
       AMD (incl. eGPU on Intel Macs) and Apple Silicon GPUs are in-OS.
    3. Network: nothing to install. Wi-Fi/Ethernet/Bluetooth are all in-OS. A PC Wi-Fi
       card cannot be transplanted into a Mac, so report rather than attempt.
    4. CPU: nothing to install - microcode and platform firmware arrive with macOS.
    5. Printers/scanners: CUPS is macOS printing and is already present; AirPrint/IPP
       Everywhere covers most printers driverless. Offer SANE (sane-backends) ONLY for a
       scanner with no macOS driver; offer the vendor package (e.g. HP Easy Start) only
       when that vendor's device is present.
    6. Fingerprint: PC readers have NO macOS driver - report "Not Supported" and point
       at Touch ID / Apple Watch unlock.
    7. FIRMWARE: `softwareupdate -l` lists pending Apple driver/firmware updates and
       `softwareupdate -ia --agree-to-license` installs them. There is no fwupd/LVFS
       equivalent and none is needed.
    8. PERIPHERAL DRIVERS macOS does not include, offered ONLY when the device is
       actually attached (match the USB vendor id in `system_profiler SPUSBDataType`):
       ftdi-vcp-driver (0x0403), wch-ch34x-usb-serial-driver (0x1a86),
       silicon-labs-vcp-driver (0x10c4), prolific-pl2303-driver (0x067b),
       wacom-tablet (0x056a). Also install Rosetta 2 on Apple Silicon.

  TRUSTED SOURCES (same hard rule as PART C)
    Apple Software Update (Apple-signed); Homebrew Cask (formula audited upstream, each
    with an upstream URL + checksum). Vendor driver casks print the exact vendor URL and
    are user-confirmed. Include the "TRUSTED SOURCES GUARANTEE" comment block at the top.

  SUMMARY
    Print Installed/Manual/Skipped(n-a)/Failed counts; list skipped (hardware absent),
    "no macOS support" (PC-only hardware) and failed items; recommend a REBOOT when a
    kernel extension was installed - and remind the user that a new kext must be
    APPROVED in System Settings > Privacy & Security before macOS will load it.

 PART F - ONE-SHOT ORCHESTRATOR  (<Target OS>/execute_all.sh)
===============================================================================
  A single entry point that runs the whole migration on the target machine.
    * Bash; cd to its own dir (SCRIPT_DIR) so child scripts resolve ../*.csv.
    * require root (children each need root).
    * DRY-RUN: --dry-run / --report-only / -n (or MIGRATE_DRY_RUN=yes) prints the
      per-app plan and changes nothing; it skips require-root and runs only the apps
      plan (driver/settings/docker stages are skipped, config is not saved).
    * For each stage IN ORDER - settings, apps, drivers -
        apply_settings.sh, install_must_have_software.sh, install_device_drivers.sh:
      chmod +x the script, then run "./<script>" inheriting the terminal (each child
      has its own clean UI + logs).
    * CONTINUE-ON-ERROR: capture each child's exit code; a failure is recorded but
      NEVER stops the remaining stages. A missing script is "MISSING", not a failure.
    * Print a per-stage OK/FAILED/MISSING summary with exit codes + elapsed time;
      exit non-zero iff any stage failed.
    * Setup answers persist to migrate.config; the LAST setup question is the optional
      Wine (Windows emulator) install for non-cross-platform apps (MIGRATE_WINE_NONCROSS).
    * Manual / download-by-user prompts use 'installer path'/skip/skip all (path in
      single quotes, full or relative to ~/Downloads). After the run, write
      uninstall_migrated_apps.sh to the user's home; installs that cannot be confirmed
      present are reported UNVERIFIED (not OK).
  Run with:  sudo ./execute_all.sh        (add --dry-run to preview without changes)
